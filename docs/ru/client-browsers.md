# Браузеры

**Русский** | [English](../client-browsers.md)

Направьте на локальный клиент xray только браузер, а не всю систему. Полезно, если
системный прокси не нужен или нужно, чтобы один браузер (или один профиль) шёл через
прокси, а другой напрямую.

**Предварительное условие**: на этом компьютере запущен xray с вашим
`<email>.config.json` (см. руководство для [Windows](client-windows.md), [Linux](client-linux.md)
или [macOS](client-macos.md)). Он слушает:

| Порт | Протокол |
|---|---|
| `127.0.0.1:10808` | SOCKS5. Предпочтительно: DNS разрешается через прокси |
| `127.0.0.1:10809` | HTTP / HTTPS |

Раздельная маршрутизация по-прежнему работает: браузер отправляет всё в xray, а xray
отправляет перечисленные в конфиге домены напрямую, а остальное через сервер. PAC-файл
не нужен.

## Firefox

У Firefox собственные настройки прокси, не зависящие от системы.

Settings («Настройки») → General («Основные») → **Network Settings** («Параметры сети») →
Settings… («Настроить…»):

1. **Manual proxy configuration** («Ручная настройка прокси»)
2. **SOCKS Host** («Узел SOCKS»): `127.0.0.1`, Port («Порт») `10808`, **SOCKS v5**
3. HTTP Proxy оставьте пустым.
4. Отметьте **Proxy DNS when using SOCKS v5** (иначе DNS-запросы уходят на ваш локальный
   резолвер и раскрывают, какие сайты вы посещаете).
5. **No proxy for** («Не использовать прокси для»): `localhost, 127.0.0.1`
6. OK.

Чтобы вернуться обратно: тот же диалог → **No proxy** («Без прокси») (или **Use system
proxy settings** («Использовать системные настройки прокси»), если настроен системный
прокси).

Отдельный профиль с прокси: откройте `about:profiles` → **Create a New Profile**
(«Создать новый профиль»), настройте прокси только в нём и запускайте его из
`about:profiles` (или `firefox -P <name>`).

## Chrome, Edge, Brave, Opera, Vivaldi (Chromium)

У браузеров на Chromium нет собственных настроек прокси: в Windows и macOS они
используют **системный прокси** (настройте его по десктопным руководствам, и браузер
будет его использовать). Для прокси только в браузере используйте флаг запуска или
расширение.

### Вариант A: флаг запуска (без расширения)

Запустите браузер с `--proxy-server`. Используйте отдельный `--user-data-dir`: флаг
игнорируется, если браузер уже запущен с тем же профилем, а отдельный профиль разделяет
работу через прокси и напрямую.

**Windows** (создайте ярлык на рабочем столе с этим объектом):

```
"C:\Program Files\Google\Chrome\Application\chrome.exe" --proxy-server="socks5://127.0.0.1:10808" --user-data-dir="%LOCALAPPDATA%\Chrome-Proxy"
```

Edge: `"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"` с теми же
аргументами (и, например, `%LOCALAPPDATA%\Edge-Proxy`).

**macOS**:

```bash
open -na "Google Chrome" --args --proxy-server="socks5://127.0.0.1:10808" --user-data-dir="$HOME/.chrome-proxy"
```

**Linux**:

```bash
google-chrome --proxy-server="socks5://127.0.0.1:10808" --user-data-dir="$HOME/.chrome-proxy"
# chromium / brave-browser / microsoft-edge принимают те же флаги
```

С прокси `socks5://` Chromium разрешает имена хостов через прокси, поэтому утечки DNS
нет.

### Вариант B: расширение для прокси

Расширение-переключатель прокси (например, **ZeroOmega**, поддерживаемый форк
SwitchyOmega) позволяет включать и выключать прокси с панели инструментов:

1. Установите его из Chrome Web Store / Edge Add-ons.
2. Создайте профиль: протокол **SOCKS5**, сервер `127.0.0.1`, порт `10808`,
   список исключений `localhost`, `127.0.0.1`, `<local>`.
3. Выберите этот профиль через значок на панели инструментов, чтобы включить прокси;
   **Direct** или **System**, чтобы выключить.

Устанавливайте расширения для прокси только из источников, которым доверяете: они видят
весь ваш трафик.

## Safari

У Safari нет собственных настроек прокси; он использует системный прокси macOS (см.
[client-macos.md](client-macos.md), раздел про системный прокси).

## Телефоны

В мобильных браузерах нет настроек прокси; приложения для [Android](client-android.md)
и [iOS](client-ios.md) туннелируют всё устройство, включая браузеры.

## Утечки WebRTC

WebRTC (видеозвонки, скрипты некоторых сайтов) может отправлять UDP напрямую, в обход
прокси, раскрывая ваш реальный IP. Если это важно:

- **Firefox**: `about:config` → установите `media.peerconnection.ice.proxy_only_if_behind_proxy`
  в `true` (WebRTC только через прокси; звонки по-прежнему работают через него) или
  `media.peerconnection.enabled` в `false` (WebRTC полностью отключён).
- **Chromium**: установите расширение Google **WebRTC Network Limiter** и выберите
  «Use my proxy server (if present)».

## Проверка

В браузере, работающем через прокси:

- `https://ifconfig.me` показывает IP **сервера**.
- В браузере без прокси та же страница показывает ваш собственный IP.
- `https://browserleaks.com/webrtc` не показывает публичных IP, кроме IP сервера
  (после настройки WebRTC, описанной выше).
- Сайт из списка прямых доменов в вашем конфиге по-прежнему должен открываться с вашим
  собственным IP.

Если страницы не загружаются: запущен ли xray (`curl -x socks5h://127.0.0.1:10808 https://ifconfig.me`)?
См. советы по устранению неполадок в [README.md](README.md).
