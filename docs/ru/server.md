# Установка и администрирование сервера

**Русский** | [English](../server.md)

Установка, проверка и эксплуатация стека на сервере с Ubuntu LTS, а также управление клиентами прокси.

Всё выполняется **на сервере**: войдите через `ssh <host>` и работайте в папке
установки. Стек устанавливается прямо из этого репозитория через `git clone`;
загружать что-либо со своего компьютера не нужно.

Везде далее: `<host>` — ваш SSH-логин (`user@1.2.3.4` или алиас из `~/.ssh/config`),
`<domain>` — ваш домен, `/opt/xray-stack` — папка установки (подойдёт любая).

## 1. Требования

- **Сервер**: Ubuntu LTS (22.04 / 24.04), 1 vCPU, минимум 1 ГБ RAM, root или sudo.
  При 1 ГБ RAM нужен swap на 2 ГБ; `install.sh` предложит его создать.
- **Домен**: запись `A` (и `AAAA`, если у сервера есть IPv6) для `<domain>`,
  указывающая на сервер и резолвящаяся **до** первого запуска (сертификат
  выпускается через порт 80).
- **Порты**: 80/tcp и 443/tcp доступны из интернета, плюс SSH.
  Больше ничего открывать не нужно.

Файрвол через `ufw` (или используйте облачный файрвол провайдера с теми же правилами):

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

Примечание: порты, опубликованные Docker, обходят `ufw` (Docker пишет собственные правила iptables).
Здесь это не проблема, так как стек публикует только 80 и 443; внутренний 8443
и база данных никогда не публикуются. Не добавляйте `ports:` другим сервисам.

## 2. Установка

```bash
ssh <host>
sudo apt-get update && sudo apt-get install -y git
sudo git clone https://github.com/iztiev/xray-proxy.git /opt/xray-stack
cd /opt/xray-stack
sudo bash install.sh
```

`install.sh`:

1. Проверяет ОС и swap (при необходимости предлагает создать `/swapfile` на 2 ГБ).
2. Устанавливает Docker Engine + плагин Compose из официального apt-репозитория Docker
   (пропускается, если уже установлены), а также `jq` и `openssl`.
3. Запрашивает:
   - **Домен**: используется для сертификата, сайта и SNI для REALITY.
   - **Email**: контакт для Let's Encrypt, логин администратора сайта и имя
     первого клиента прокси.
   - **Пароль администратора** сайта (ввод скрыт, минимум 8 символов, без `'`).
4. Генерирует все секреты: секреты базы данных/JWT из 64 hex-символов, пару ключей REALITY,
   UUID и short ID первого клиента.
5. Рендерит `templates/` в папку установки, проверяет всё
   (`docker compose config`, `xray run -test`).
6. Спрашивает, запустить ли стек и показать ли QR-код первого клиента.

Повторно он запускаться отказывается (если существует `.env` или `xray/server.json`): новые
секреты базы данных лишили бы сайт доступа к его существующей базе.

После первого запуска выполните рекомендацию, которую выводит `install.sh` после установки
(уменьшите число воркеров веб-приложения для сервера с 1 ГБ, затем перезапустите этот сервис).

### Что оказывается на сервере

Рядом с файлами репозитория, всё в git-ignore:

| Путь | Содержимое | Секрет |
|---|---|---|
| `.env` | домен, email-адреса, секреты базы данных/JWT, пароль администратора | да (600) |
| `compose.yml`, `Caddyfile` | описание стека, отрендеренное из `templates/` | нет |
| `xray/server.json` | приватный ключ REALITY, UUID и short ID всех клиентов | да |
| `xray/server.json.bak-*` | резервные копии, созданные `add_user.sh` / `remove_user.sh` | да |
| `clients/<email>.config.json` | конфиг клиента для компьютера | да |
| `clients/<email>.link.txt` | ссылка для импорта (share link) `vless://` (телефоны, GUI-приложения) | да |
| `data/` | сертификаты, база данных, файлы сайта | да |

## 3. Проверка

На сервере:

```bash
cd /opt/xray-stack
sudo docker compose ps                     # все сервисы "running" / "healthy"
sudo docker compose logs --tail 50         # ищите ошибки
free -m && sudo docker stats --no-stream   # запас памяти
```

С любой машины:

```bash
curl -sI https://<domain>             # HTTP 200/302 от сайта, валидный сертификат
```

Браузер, открывший `https://<domain>`, должен показать сайт с валидным
сертификатом: именно это видит каждый посетитель, не являющийся клиентом, и каждый сканер.

Затем подключите клиента: см. [README.md](README.md).

## 4. Управление клиентами

На сервере, в папке установки (`cd /opt/xray-stack`). Используйте отдельного клиента для каждого
устройства; тогда потерянное устройство можно отозвать по отдельности.

### Добавление

```bash
sudo bash add_user.sh
```

Запрашивает email (любую уникальную метку в формате email), затем добавляет UUID и short ID
в `xray/server.json` (с проверкой, предыдущая версия сохраняется как резервная копия), записывает
`clients/<email>.config.json` и `.link.txt` и предлагает перезапустить xray.
**Ответьте y**: новый клиент заработает только после перезапуска (существующие соединения
ненадолго оборвутся). В конце предлагает показать QR-код.

### Показ QR-кода (телефоны)

```bash
sudo bash show_qr.sh             # выбрать из списка
sudo bash show_qr.sh <email>     # напрямую
```

Отсканируйте его в v2rayNG (Android) или Streisand / V2Box / Shadowrocket (iOS). Используйте
терминал достаточного размера, чтобы код поместился целиком, и выполните после этого `clear`: код
является учётными данными.

### Как перенести файлы клиента на компьютер

Клиентам для компьютера нужен `clients/<email>.config.json`. Либо выведите его на
сервере и вставьте в файл на компьютере:

```bash
sudo cat clients/<email>.config.json
```

либо скопируйте его через `scp`, выполнив **на компьютере** (работает в Windows Terminal, macOS
и Linux; если скрипты запускались через `sudo`, владельцем файлов является ваш SSH-пользователь):

```bash
scp "<host>:/opt/xray-stack/clients/<email>.*" .
```

### Удаление

```bash
sudo bash remove_user.sh
```

Выводит пронумерованный список клиентов, спрашивает, какого удалить, и просит подтверждения. Удаляет его UUID и
short ID из `xray/server.json` (с проверкой и резервной копией), удаляет его файлы клиента
и предлагает перезапустить xray; после перезапуска клиент теряет доступ. Последнего
оставшегося клиента удалить нельзя (сначала добавьте другого). Учётные записи сайта это не
затрагивает.

## 5. Эксплуатация

Всё в папке установки (`cd /opt/xray-stack`):

| Задача | Команда |
|---|---|
| Статус | `sudo docker compose ps` |
| Логи (в реальном времени) | `sudo docker compose logs -f --tail 100` (или `… logs -f xray`) |
| Перезапустить только xray | `sudo docker compose restart xray` |
| Остановить / запустить всё | `sudo docker compose down` / `sudo docker compose up -d` |
| Обновить образы контейнеров | `sudo docker compose pull && sudo docker compose up -d` |
| Удалить старые образы | `sudo docker image prune -f` |

Стек автоматически перезапускается после перезагрузки (`restart: unless-stopped`).

### Обновление скриптов

```bash
cd /opt/xray-stack
sudo git pull
```

Отрендеренные конфиги, файлы клиентов и `data/` находятся в git-ignore, поэтому pull обновляет только
скрипты, шаблоны и документацию; ваши секреты и клиенты не затрагиваются. Pull
**не** перерендеривает существующие конфиги: если в релизе изменился шаблон, перенесите это
изменение в отрендеренный файл вручную (сохранив его секреты), затем перезапустите затронутый
сервис.

### Резервные копии

Всё необходимое для восстановления находится в папке установки: `.env`, `xray/`, `clients/`
и `data/`. Для согласованной копии базы данных остановите стек:

```bash
cd /opt/xray-stack
sudo docker compose down
sudo tar czf /root/xray-stack-$(date +%F).tgz .env compose.yml Caddyfile xray clients data
sudo docker compose up -d
```

Архив содержит все секреты; храните его в зашифрованном виде и не на сервере.

## 6. Устранение неполадок

| Симптом | Что проверить |
|---|---|
| У сайта нет сертификата / он невалиден | DNS указывает на сервер? Порт 80 открыт? `sudo docker compose logs caddy` |
| Сайт работает, клиенты не могут подключиться | xray перезапущен после `add_user.sh`? `sudo docker compose logs xray`; часы устройства верны (REALITY отклоняет расхождение >~2 мин) |
| Не работает только в некоторых сетях | Эти сети блокируют или замедляют 443/tcp до сервера; проблема не в конфиге |
| Контейнеры перезапускаются / убиваются | Нехватка памяти: `free -m`, `docker stats`, `dmesg \| grep -i oom`; swap включён? |
| `install.sh` отказывается запускаться | Уже установлено. Управляйте клиентами скриптами выше; никогда не удаляйте `.env` на сервере, где сайт уже запускался |
| `lib.sh … is outdated` / `command not found` | Скрипты и `lib.sh` рассинхронизированы: `sudo git pull` обновляет их вместе |
| `git pull` жалуется на локальные изменения | Отслеживаемый файл был изменён на сервере: `sudo git status`, затем `sudo git stash` или `sudo git checkout -- <file>` |
